## 〇、一句话总结

联邦运行 48h 的全部容灾事故，根因都收敛到同一条规律：**凡依赖"会话活着"的机制都会死，凡落在文件与进程上的机制都活了**——零 token 层（keeper/看门狗/值影/心跳双写）是全部可用性的来源，模型层只应在事件驱动时被唤醒。

## 一、复盘案例（五案 + 两发现）

### 案例 1：01:00 5h 配额熔断（2026-09-06）
- **经过**：常驻值守子 agent 上岗 46 秒即撞 5 小时使用上限；已挂 15:26 定时重启验证自愈可行。
- **根因**：编码计划额度是**会话共享池**——主会话耗尽后，任何模型层进程（含子 agent）上岗即死；子 agent 不增加容量，只多一张嘴。
- **失效的方案**：常驻子 agent 站岗、模型级定时轮询。
- **有效的方案**：零 token 层完全隔离（keeper/看门狗/值影全程无恙，事故期间反重力侧 Tab1 施工照常）。
- **沉淀**：额度经济学铁律——**探测与等待永远不花 token，模型只在事件驱动时唤醒**；长活任务优先派反重力（Gemini 额度池独立）。

### 案例 2：夜间 12.5h 心跳停摆（2026-09-05→06）
- **经过**：各席会话关闭，全员心跳停 ~12.5h；指挥官"发信自动心跳"改造后经 #51 PING 验证可唤醒。
- **根因**：心跳依附会话生命 = 单点。会话是间歇的，心跳必须是常驻的。
- **沉淀**：FED-OPS v1.0 落地的 I1 开机自启 + I2 心跳双写（HEARTBEATS\<agent>.json）+ keeper 常驻补位，把"心跳"从会话职责剥离为系统职责。

### 案例 3：值影节奏 90s×200min → 90s×8min（2026-09-06 本会话）
- **经过**：交接包指定 90s×200min 值影；接棒后发现 WORKMODE 租约判定为 `now-mtime ≤ 600s`，200min 静默会让租约在第 10 分钟被判假死（读者自愈机制反而误伤长值守）。
- **修正**：值影 8min 超时退出 → task-notification 唤醒当值会话刷 mtime → 续挂。**超时退出兼作循环节拍**，一拍两用。反重力侧 #100 已确证总台租约计算与此正交兼容。
- **附带发现 A（操作纪律）**：`shell 内 & 后台 + 会话任务托管`混用会产生脱离通知管理的孤儿进程（04:22 已修正为规范 run_in_background 单一托管）。

### 案例 4：check_workmode_lease.py 归档误伤（2026-09-06 本会话）
- **经过**：议题 B 归档 108 件后靶场首跑 7/8——case_04 失败，因被归档脚本是黄金靶场活依赖。
- **根因**：依赖扫描只覆盖了本仓 grep 引用，漏掉**外部 JSON 间接引用层**（用例定义在 `repo:docs/eval_golden\case_04_workmode_lease.json` 的 cmd 字段）。
- **修正**：脚本归位，复跑 8/8；教训写入 MANIFEST 修正记录。
- **沉淀**：**裁撤/归档判定三查**——①本仓 grep 引用；②eval_golden 用例 cmd 字段；③活链路（通知/自启/挂账）逐一豁免。此条应入 skills/federation-protocol。

### 案例 5：多写者并发写 STATUS.md（2026-09-06 本会话 ×2）
- **经过**：本会话两次 Edit 撞"文件已被修改"（反重力新会话同步状态），均重读后增量合并，无覆盖损失。
- **根因**：STATUS.md 实为多写者共享文件（违反单写者精神），靠乐观锁+人工合并兜底。
- **沉淀**：短期纪律——写前必读、冲突即重读增量合并；长期可选——STATUS 拆为各席分节独占，或迁入桥 DB 只留一份渲染层。

### 发现 B：激活问题的架构结论（回应指挥官 flash 额度之问）
- **子 agent 活不过会话**——它不是关闭态激活的解；会话开着时值影已 0 token 覆盖。
- 关闭态缺的是"传呼"：keeper(0 token 探测) + 飞书机器人(0 token 传呼人) 已就位。
- **flash 唯一正确落位**：keeper `--hook` API 直调分诊层（~2K token/次，日量级 10 万 token 内，走 API 计费不占编码计划额度池）——待指挥官提供 GLM API key 即接，接后 24h 实测入 USAGE_LOG。
