# 多智能体协作工作流（moa v2）

> 来源：指挥官定调——"可以对话的那个 MOA 向的工作流，作为 MOA skill 正儿八经解决工作"（2026-09-13）；
> **正名（指挥官钦定 2026-09-13）：MOA 本体 = :8765 DSH 思考座舱系统**（消化道流水线工作流 + 各席位独立对话框）——评测侧的并行聚合脚本（moa_mixture.py）只是辅助工具，不称本体。
> 定位：联邦的协作操作系统。模型评测为"选角"模块。

## 一、三大模块

### 模块 1：对话式工作流（秘书长座舱模式 · 反重力已实装 :8765）
**实体实现即 DSH 思考座舱 v1.2.0**（`http://127.0.0.1:8765`，WindyElk 构建），三区联动：
- **战略意图收敛区**（左）：四脑模式按钮——`Gemini 3.1 秘书长`（1M 上下文全景规划）/ `DeepSeek 红队挑刺`（冷酷审计）/ `双脑合议对勘`（两模型对照推演）/ `T-1 防偏航审计`（第三人称中立观测）；
- **联盟自治流水线**（中）：桥公文实时流（工单-回执全链可视化）；
- **Crystal Diff 断面**（右）：施工 diff + HASH 指纹 + 指挥官 `批准合流/一票否决`——验收闭环 UI。
工作流：指挥官在座舱提想法 → 四脑推演收敛 → "提炼为 Spec"一键派工 → Builder 施工 → Diff 断面呈批。
- 降级路径：座舱不在线时协调席代行（读 STATUS→对齐→派单）。

### 模块 2：岗位-模型选角（v1 评测能力）
岗位说明书制：先定角色需求（上下文/推理/成本/延迟），再实测选角。
- 评测双通道：直连 harness（`bench\llm_bench.py`）/ DSH 工单通道（`dsh_bench.py`）；
- 进阶基准：`bcb_hard.py`（BigCodeBench-Hard 148 题，GPT-5.6 Sol 锚 42.6%）；
- 现行矩阵：Builder=GLM 5.3 / 秘书=Gemini 3.1 Pro / 看管与轻施工=GLM 5.3 Flash / 清洗=DeepSeek v4.1 Flash / 值守=脚本+行动级 flash；
- 更换逻辑：旗舰代差 / 连续故障 3 次 / 岗位需求变化 → 看管者登记 + 评测过靶 + 指挥官批。

### 模块 3：协作纪律
- 派单五要素：主题前缀 [TASK-ID]、topic、reply 保线程、署名块（v1.2.2）、OPEN 立项信（v1.2.1）；
- 防撞车：并行施工前互通报文件清单；key 共用提前报备；总台重启只归看门狗；
- 身份铁律：对话框-身份 1:1，发信零 fallback，不冒名不代签；
- 验收：靶场全绿 + 人工实点 + RESULT 信附 diff 与 SHA-256 指纹。

## 二、混合解题引擎（MOA 本体：多模型同时跑）

同一任务多模型并行作答 → 聚合出终答，量化协同增益：
- **聚合三级**：①单模型基线分；②MOA-pass@k（任一通过即联合通过，验证择优）；③旗舰仲裁层（全错题交强模型看多答案融合，经典 MoA 论文架构）；
- 引擎：`bench\moa_mixture.py`（同 judge 管道判定，判定缓存防重跑）；
- 实验一（进行中）：BCB-Hard 40 题同卷，DeepSeek flash + Gemini 3.8 flash 双跑 → pass@2 对照；失败题留旗舰仲裁；
- 价值主张：单模型各对四成的硬题，多模型联合预期过半——协同增益即 moa 存在的理由。
